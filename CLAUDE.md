## What this project does
Hover a YouTube thumbnail in Brave/Chrome/Aside → press **Alt+A** on Windows → AutoHotkey triggers the extension with F24, reads the copied YouTube URL, then sends the URL plus Korean summary suffix to the preferred Gemini desktop app (Chrome Gemini PWA is the fallback). **Alt+Z** (Aside only) does the same copy but sends it to Aside's built-in AI side panel; on a Netflix tab in Aside it instead copies the current subtitle line (Ctrl+C) and asks the panel to interpret it in Korean.

## Windows / macOS / Linux components
1. **Browser extension** ([content.js](content.js)) — tracks the hovered video and writes its URL to the clipboard when it receives F24.
2. **Windows AHK v2 script** ([copy.ahk](copy.ahk)) — `$!a::` → `RunFlow("gemini")`: confirms the clipboard change, then uses Windows UI Automation to fill Gemini desktop's composer and invoke Send (Chrome PWA flow only when the desktop app is absent). `$!z::` → `RunNetflixExplain()` if the foreground Aside title contains `Netflix`, else `RunFlow("aside")`. Helpers: `scripts/send_gemini_desktop.ps1`, `scripts/send_aside_panel.ps1`.
3. **Gemini desktop app** — receives the URL and `한국어로 요약해 줘`; the user can continue the conversation in the app.
4. **Aside browser AI side panel** (Alt+Z) — in the same Aside window; model/provider is configured in Aside (`Settings > Models`; custom providers in `~/.aside/u/0/models.json`, `apiKey` may name a user env var such as `EZURIO_GATEWAY_VIRTUAL_KEY` — Aside must be restarted after that variable changes).

No background script, no native messaging, no host permissions beyond the YouTube content-script match.

## Reported problem
"Copy feature sometimes works but sometimes does not." Logs in [copyurl_log.txt](copyurl_log.txt) show clusters of `Copy attempt N timed out` with no diagnostic about *which* leg failed (extension didn't fire? `hoveredVideoUrl` null? execCommand returned false? OS clipboard never updated?).

## Suspected root causes (ranked)
0. **(FIXED 2026-05-02) Alt+X collision with CopyAnkitoChatGPT**: that app's global Alt+X hook intercepted the synthetic Alt+X before it reached Brave, so the extension never received the keydown. Replaced with **F24** (no global binding).
1. **execCommand → async fallback race**: `execCommand` returns false; code calls `navigator.clipboard.writeText` (async); AHK's per-attempt 1500 ms clipboard-sequence wait can expire before the promise resolves.
2. **Stale `hoveredVideoUrl`**: `mouseout` cleared it; `refreshHoverFromLastPointer()` couldn't re-find from stale coordinates after window activate.
3. **Pre-copy `SendInput("{Escape}")`** ([copy.ahk](copy.ahk)) blurs/cancels page state in unhelpful ways.
4. **MV3 re-injection race**: tab reload / SPA navigation before listener attached.

## Plan (6 phases — Phase 2 is tracked as issue #3; the rest is historical)
- **Phase 0** *(this commit)*: handoff scaffolding — `CLAUDE.md`, `docs/troubleshooting.md`.
- **Phase 1**: opt-in instrumentation — content.js ring-buffer + `document.title` beacon `[CU:ok|null|err|busy]`; copy.ahk pre/post-title logging + per-stage timing; log rotation.
- **Phase 2**: stress harness — `scripts/stress_copy.ahk` + `scripts/analyze_stress.py`. **Never implemented** (issue #3); the hermetic orchestrator tests added 2026-10-26 cover the logic but not repeated hover-to-clipboard runs.
- **Phase 3**: targeted fixes A–E (async-clipboard race, stale hover, Escape, MV3 readiness, Alt collision) — each independently revertable, each gated by N=200 stress run.
- **Phase 4**: validation (≥99% success, zero "no-beacon" outcomes).
- **Phase 5**: default flags OFF, instrumentation stays.

## Title beacon protocol (contract)
After every F24 keydown the extension processes, it appends ` ​[CU:STATE]` (zero-width-space + tag) to `document.title` for ~300 ms, then restores. STATE ∈ `ok | null | execfail | asyncok | asyncfail`. AHK reads via `WinGetTitle` immediately after sending F24 and parses the tag with `RegExMatch`.

## Testing
`npm test` (= `scripts/run_tests.sh`) runs, in order: JS syntax, manifest validity, the headless `gemini.js` DOM mock, the real unpacked extension end-to-end (puppeteer-core), and the **hermetic Linux orchestrator tests**. The last one needs no desktop — it runs the genuine `Linux/copyurl.sh` with shimmed `ydotool`/`xclip`/`wl-*`/`gdbus` and a file-backed clipboard, covering success, retry, total failure (clipboard restored), the sentinel/stale-clipboard false positive, `--aside`, and backend selection.

CI ([.github/workflows/tests.yml](.github/workflows/tests.yml)) runs that suite on every push/PR. It installs **Chrome for Testing**, not branded Chrome: branded Google Chrome removed `--load-extension` outright (crbug 401529219), so the unpacked extension silently never loads there and the e2e test fails with a bare `toast=null`. The e2e launchers detect branded Chrome by `--version` and skip it. Two things deliberately SKIP in CI: the full-system test (`COPYURL_FULL_SYSTEM=1`, needs Wayland + ydotoold + a headful browser) and `Mac/check_live_sync.sh` (needs the live `~/.hammerspoon/init.lua` — see issue #4).

The e2e tests read the prompt wording from `content.js` (`readPasteSuffix()`) instead of hardcoding it, so rewording cannot silently desync the test — while a wrong/stale URL still fails.
